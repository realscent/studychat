# 신성대 스마트드론건설

컴퓨터실 강의에서 학생들의 작업 완료 여부를 실시간으로 확인하는 웹 앱입니다.

## 기능

- 접속 중인 사용자 수 표시
- 같은 브라우저의 여러 탭은 한 명으로 집계하고 기존 세션으로 자동 입장
- 운영자 로그인 세션은 접속자 수와 목록에서 제외
- 한 브라우저는 사용자 또는 운영자 중 하나의 역할만 사용
- 사용자 닉네임 입장 및 접속 목록 표시
- 실시간 채팅
- 긴 채팅 말풍선 더보기/접기
- 채팅 첨부파일 공유 및 여러 파일 묶음 전송
- 이미지/동영상 썸네일과 클릭 미디어 뷰어
- 미디어 뷰어 확대/축소, 휠 확대, 드래그 이동
- 동영상 모달 재생
- 복사한 이미지를 채팅 입력창에 붙여넣어 전송
- 운영자 전용 푸쉬버튼
- 푸쉬 진행 중 미완료 사용자는 빨간색, 완료 사용자는 초록색 표시
- 모든 사용자가 누르면 운영자에게 완료 창 표시
- 운영자가 `OK`를 누르면 푸쉬 상태 초기화
- 운영자 화면에서 접속자 IP 표시
- 운영자 강퇴 및 IP 차단
- 차단 IP 목록 표시 및 차단 해제
- 운영자 채팅 우클릭 삭제
- 신성대학교 로고 기반 화면 디자인

## 로컬 실행

```powershell
npm install
$env:ADMIN_PASSWORD="원하는_비밀번호"
npm start
```

브라우저에서 `http://localhost:3000`으로 접속합니다.

기본 운영자 비밀번호는 `admin1234`입니다. 실제 사용 시 반드시 `ADMIN_PASSWORD` 환경 변수로 변경하세요.

## 교실 LAN에서 바로 사용

교사 PC에서 서버를 실행한 뒤 같은 교실 네트워크에 있는 학생들은 교사 PC의 IPv4 주소로 접속하면 됩니다.

```powershell
ipconfig
```

예를 들어 교사 PC의 IPv4 주소가 `10.1.3.132`라면 학생들은 아래 주소로 접속합니다.

```text
http://10.1.3.132:3000
```

학생 PC에서 접속이 안 되면 Windows 방화벽에서 TCP `3000` 포트 인바운드 허용이 필요할 수 있습니다.

같은 교실 LAN에서 교사 PC로 직접 접속하면 학생 PC마다 보통 `10.x.x.x`, `192.168.x.x` 같은 서로 다른 사설 IP가 보입니다. 외부 서버로 배포하면 학교 공유기나 프록시 때문에 여러 학생이 같은 공인 IP로 보일 수 있습니다. 이 경우 한 명을 IP 차단하면 같은 IP로 보이는 다른 학생도 같이 차단될 수 있습니다.

같은 학생이 한 브라우저에서 여러 탭을 열어도 새 탭은 기존 세션으로 자동 입장하고 접속자는 한 명으로만 계산됩니다. 운영자 화면에는 해당 학생 행에 탭 수가 표시됩니다. `나가기`를 누르기 전까지 같은 브라우저는 기존 사용자 또는 운영자 역할을 유지하며, 사용자와 운영자를 동시에 사용할 수 없습니다.

## GitHub Pages로 바로 호스팅할 수 없는 이유

이 앱은 실시간 접속자 수, 닉네임 목록, 채팅, 푸쉬 상태, IP 차단 목록을 서버에서 관리하고 Socket.IO로 즉시 전송합니다.

GitHub Pages는 HTML, CSS, JavaScript 같은 정적 파일을 올리는 용도라 Node 서버를 실행하지 못합니다. 그래서 이 프로젝트를 GitHub Pages에 그대로 올리면 화면 파일은 보일 수 있어도 실시간 서버 기능은 동작하지 않습니다.

아무 곳에서나 접속하려면 아래 중 하나가 필요합니다.

- Render, Railway, Fly.io, VPS 같은 Node 서버 호스팅
- Jenkins가 배포할 수 있는 공개 서버
- Firebase/Supabase 같은 실시간 백엔드로 구조 변경 후 GitHub Pages 정적 호스팅

## GitHub 업로드

GitHub에서 빈 저장소를 만든 뒤 아래 명령을 실행합니다.

```powershell
git init
git add .
git commit -m "Initial classroom button push site"
git branch -M main
git remote add origin https://github.com/<GitHub아이디>/<저장소이름>.git
git push -u origin main
```

현재 작업 환경에는 GitHub 저장소를 자동 생성할 수 있는 `gh` CLI나 GitHub 커넥터가 없어 원격 저장소 생성은 직접 한 번 필요합니다.

## Jenkins 설정

1. Jenkins에서 Pipeline 프로젝트를 생성합니다.
2. GitHub 저장소 URL을 SCM으로 연결합니다.
3. Script Path는 `Jenkinsfile`로 둡니다.
4. Jenkins 환경 변수 또는 Credentials로 `ADMIN_PASSWORD`를 설정합니다.
5. Jenkins 서버에서 Docker로 바로 실행하려면 `DEPLOY_ON_JENKINS_HOST=true`를 설정합니다.

`DEPLOY_ON_JENKINS_HOST`를 켜지 않으면 Jenkins는 설치, 테스트, Docker 이미지 빌드까지만 수행합니다.

## 운영 방식

학생은 닉네임으로 입장합니다. 운영자는 운영자 비밀번호로 로그인합니다.

운영자가 `푸쉬버튼`을 누르면 접속 목록이 진행 상태 색상으로 바뀌고, 학생 화면에는 완료 버튼이 표시됩니다. 학생이 버튼을 누르면 해당 학생은 초록색으로 바뀝니다. 모두 완료되면 운영자에게 완료 창이 뜨며, `OK`를 누르면 색상이 초기화됩니다.

운영자는 접속 목록에서 사용자 IP를 볼 수 있고 `강퇴`를 누르면 해당 IP가 차단 목록에 들어갑니다. 같은 IP로 접속 중인 사용자는 모두 나가며, 차단 해제 전까지 학생으로 입장할 수 없습니다. 운영자는 차단 IP 목록에서 `해제`를 눌러 다시 입장을 허용할 수 있습니다.

운영자는 채팅 메시지를 우클릭해 삭제 여부를 확인한 뒤 삭제할 수 있습니다.

채팅창의 `첨부` 버튼으로 파일을 보낼 수 있습니다. 여러 파일을 한 번에 선택하면 최대 12개씩 묶음 메시지로 표시됩니다. 이미지는 썸네일을 클릭하면 큰 화면 모달로 열리고, 동영상은 모달에서 플레이어로 재생됩니다. 미디어 뷰어에서는 마우스 휠이나 `+`, `-` 버튼으로 확대/축소하고, 확대 후 드래그로 화면을 이동할 수 있습니다. 일반 파일은 다운로드 링크로 표시됩니다. 화면 캡처나 복사한 이미지는 채팅 입력창에 붙여넣으면 바로 전송됩니다. 기본 업로드 제한은 파일당 50MB, 한 묶음당 150MB이며 `MAX_UPLOAD_BYTES`, `MAX_UPLOAD_BATCH_BYTES` 환경 변수로 조정할 수 있습니다.

긴 채팅 메시지는 처음에는 일부만 보이고 `더보기` 버튼으로 펼칠 수 있습니다.
